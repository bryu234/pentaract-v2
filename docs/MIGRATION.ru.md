# Перенос Pentaract на другой сервер

Нужны Docker с Compose v2, Git, Make и lsof или ss. Сами файлы остаются в Telegram: переносим только каталог БД, мастер-ключ и настройки. Используйте тот же бот и канал. На новом сервере берите ту же или совместимую более новую версию проекта.

## Резервная копия без переезда

На работающем сервере, в каталоге проекта:

```sh
make migration-export
```

Команда кратко остановит приложение, создаст папку `data/backups/migration-<UTC>/` и запустит приложение обратно, если оно работало. Незавершённые загрузки нужно сначала завершить либо удалить. Если экспорт не удался, приложение также запускается обратно.

В папке находятся `master.key` (base64), `database.dump` и `restore.json` с настройками Telegram и контрольными суммами. Комплект НЕ зашифрован. Любой, кто его получил, получает доступ к секретам хранилища. Сохраните копию вне сервера и не публикуйте её.

Отдельные команды:

```sh
make export-key
make backup-db
```

Первая сохраняет ключ в `data/backups/master.key`, отказываясь перезаписывать существующий файл. Вторая создаёт снимок БД `data/backups/database-<UTC>.dump` без остановки сервиса; для автоматического переноса используйте именно полный комплект, а не один дамп.

## Окончательное переключение

Сначала завершите загрузки. Затем на старом сервере:

```sh
make migration-handoff
```

Команда создаёт НОВЫЙ финальный комплект, выходит из старого Bot API и оставляет старое приложение и Bot API остановленными. БД и тома сохраняются. Для переноса используйте папку, указанную именно этой командой, чтобы не потерять изменения после более ранней копии. Не запускайте одновременно две установки с одним ботом.

Скопируйте три файла из папки комплекта на новый сервер защищённым способом, например через scp. Не передавайте их через публичные ссылки.

## Новый сервер

```sh
git clone https://github.com/bryu234/pentaract-v2.git
cd pentaract-v2
# Поместите master.key, database.dump и restore.json рядом с Makefile.
make migration-restore PUBLIC_URL=http://NEW_SERVER_IP:8088
```

Для другого порта:

```sh
make migration-restore PUBLIC_URL=http://NEW_SERVER_IP:8090 PORT=8090
```

Если комплект лежит отдельно, добавьте `MIGRATION_DIR=/absolute/path/to/backup`.

Не запускайте `make init` или `make up` до восстановления. Нужен свежий клон без server/NPM override, остановленное приложение и пустая БД. Команда проверяет файлы и свободный порт, создаёт `.env` с новым паролем PostgreSQL, устанавливает ключ, собирает образы, восстанавливает БД и запускает сервис. Первая сборка Bot API может занять значительное время.

Откройте указанный адрес. Логин, пароль и TOTP прежние; старые сессии очищены, ссылки скачивания отозваны. Проверьте список папок и скачайте один самый маленький файл. HTTP используйте в доверенной сети/VPN; домен и HTTPS подключаются отдельно. После этого измените PUBLIC_URL и настройки Secure-cookie под HTTPS.

## Ошибки и возврат

При непустой БД или несовпадающих ключах восстановление останавливается, не удаляя данные. Если импорт уже выполнен, но проверка Telegram или запуск не удались, устраните причину и используйте `make up`; повторный импорт поверх существующей БД запрещён. При неудаче handoff проверьте вывод: приложение возвращается в прежнее состояние, но Bot API при необходимости запустите `docker compose start telegram-bot-api`.

Для возврата на старую установку сначала остановите новую, выполните выход бота с нового Bot API, если он там использовался, затем запустите старую. Не удаляйте старые тома до проверки нового сервера.

Зашифрованные `make backup` / `make restore` и восстановление из каталога Telegram по-прежнему доступны: [Recovery guide](RECOVERY.md).
